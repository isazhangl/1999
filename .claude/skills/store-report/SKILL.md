# 门店周报

用户的约定：**说「做周报」或只发 Excel，就按这个模板做，不要再问口径、格式和周的划分。**
这套模板（Excel 报表 + 看板截图 + 中文汇报）是用户 2026-10-19 定下的「周报」，照做即可。

- 门店：Ibirapuera（第一家）、Morumbi（第二家），每家店各发一个明细 Excel、各出一份周报。
- 用户说「做周报」但还没发文件 → 请用户把各门店的售出明细 Excel 发过来（每周一导出的那份）。

## 步骤

1. 每个上传的 Excel 复制到 scratchpad 里各自新的空目录（不要在仓库里放客户数据）。
2. 每个文件生成一份周报（输出放 `reports/`，该目录已 gitignore，用户可在 App 里打开）：
   ```bash
   mkdir -p reports
   python3 -I analytics/store_report/store_report.py <输入.xlsx> -o "reports/周报_<门店>_<开始>_<结束>.xlsx"
   ```
   - 先不带 `-o` 跑一次也行：控制台第一行会打印识别出的门店和日期区间。
   - 门店按「权益归属门店」自动识别；识别不出来，或和用户说的不一致 → 问用户，然后加 `--store <门店>`。
   - 文件跨多个月 → 问用户要哪个月，或加 `--month YYYY-MM`。
   - 周度默认按 1–7 日一段（用户 2026-10 确认过），用户明确要求才加 `--weeks natural`。
3. 重算公式（必须做）：报表里有公式，没有缓存值时，用户在 Excel「受保护的视图」或 App 预览里会看到空格。
   用 `find / -path "*xlsx/scripts/recalc.py" 2>/dev/null | head -1` 找到 xlsx skill 的 recalc.py，
   在它所在目录运行 `python3 recalc.py <输出文件> 90`，确认 `total_errors: 0`。
   找不到就跳过，并提醒用户在 Excel 里点「启用编辑」后数字才会算出来。
4. 看板截图：复制一份报表到 scratchpad，`soffice --headless --convert-to pdf`，
   再 `pdftoppm -r 100 -png -f 1 -l 1` 得到第 1 页（看板）。打开看一眼确认图表正常。
5. 用 SendUserFile 发：每家店的周报 Excel + 看板截图。然后严格按 `周报汇报模板.md` 用中文写汇报。
   脚本输出里所有 ⚠ 提示（新支付方式、新类型、跨月、缺日期、目标月份不符等）必须写进汇报。
6. 不要提交输入或输出的 Excel。报表本身是中葡双语（给巴西同事看），给用户的文字汇报用中文。
7. 目标自动读 `analytics/store_report/targets/<门店>/<YYYY-MM>.json`。没有当月目标文件时照常出周报
   （不含目标部分），并在汇报最后提醒用户发这个月的目标。

## 用户发来新目标时

目标按门店分开：按 `targets/Ibirapuera/2026-10.json` 的格式写 `analytics/store_report/targets/<门店>/<YYYY-MM>.json`
（月目标 + 每日目标；用户只给每日目标表时它就是权益金目标，其他指标按用户说的填），提交并推送
（目标文件不含客户信息，可以入库）。用户只给总数要求调整时（例如「总目标降到 X，其他按比例」），每日目标按比例缩放、
四舍五入到整数、零头放在最后一天，保证合计等于新总数。「客单价」= 体验客单价；比率目标写小数（20% 写 0.2）。

## 口径（已与用户 2026-10 手工透视表逐项核对，不要擅自改）

详见 `analytics/store_report/README.md`。要点：权益金 = 权益类实收（排除线上开业券、代金券/套餐抵扣部分）；
营业额 = 项目支付金额；客次 = 项目行数（组合支付的「数量 0」拆分行不算）；会员 = 套餐核销；网红/邀约 = 免单类；
成交人数 = 买套餐的去重客户；二次券 = 现场掏钱买的代金券张数；叠加率 = 全部行数量合计 ÷ 总客次；
新客成交率 = 成交人数 ÷ 新客客次；员工「业绩」= 该员工名下权益金（明细里「实业绩」列为 0）。

用户要求改口径时，改 `store_report.py` 并同步更新 README 与本文件；改完先用上一份明细跑一遍，确认没改的指标数字不变。
