# 门店经营报表

用户的约定：**以后只发 Excel，不用再解释**。拿到文件就按下面跑，不要再问口径。

## 步骤

1. 把上传的 Excel 复制到 scratchpad 里一个新的空目录（不要在仓库里放客户数据）。
2. 生成报表（输出放 `reports/`，该目录已 gitignore，用户可在 App 里打开）：
   ```bash
   mkdir -p reports
   python3 -I analytics/store_report/store_report.py <输入.xlsx> -o "reports/门店经营报表_<开始>_<结束>.xlsx"
   ```
   - 文件跨多个月 → 问用户要哪个月，或加 `--month YYYY-MM`。
   - 用户说要按自然周 → 加 `--weeks natural`。
3. 重算公式（必须做）：报表里有公式，没有缓存值时，用户在 Excel「受保护的视图」或 App 预览里会看到空格。
   用 `find / -path "*xlsx/scripts/recalc.py" 2>/dev/null | head -1` 找到 xlsx skill 的 recalc.py，
   在它所在目录运行 `python3 recalc.py <输出文件> 90`，确认 `total_errors: 0`。
   找不到就跳过，并提醒用户在 Excel 里点「启用编辑」后数字才会算出来。
4. 用 SendUserFile 把报表发给用户，然后用中文简短汇报：
   - 月度 12 个指标（权益金、营业额、总客次、会员客次、新客客次、网红/邀约、成交人数、成交客单、二次券成交数、体验客单价、叠加率、新客成交率）
   - 各周对比的亮点 / 异常（例如某周客次或权益金明显下滑；进行中的周数据不完整要说明）
   - 员工达成前几名、各人周度走势的明显变化，以及「未指定员工（线上购券）」金额
   - 项目分类：客次/营业额占比最高的分类和项目，新客 vs 会员偏好的差异
   - 脚本输出里所有 ⚠ 提示（新支付方式、跨月、缺日期等），这些可能影响口径，必须告诉用户
5. 不要提交输入或输出的 Excel。
6. 有目标时（自动读 `analytics/store_report/targets/<YYYY-MM>.json`）汇报里加上各目标的月达成率、同期达成 ✓/✗、
   以及权益金/营业额「剩余营业日日均需完成」。没有当月目标文件时提醒用户发目标。

## 用户发来新目标时

按 `targets/2026-10.json` 的格式写 `analytics/store_report/targets/<YYYY-MM>.json`（月目标 + 每日目标），提交并推送
（目标文件不含客户信息，可以入库）。用户只给总数要求调整时（例如「总目标降到 X，其他按比例」），每日目标按比例缩放、
四舍五入到整数、零头放在最后一天，保证合计等于新总数。「客单价」= 体验客单价；比率目标写小数。

## 口径（已与用户 2026-10 手工透视表逐项核对，不要擅自改）

详见 `analytics/store_report/README.md`。要点：权益金排除开业券（线上已付）；营业额=项目支付金额；
客次=项目行数；会员=套餐核销；网红/邀约=免单类；成交人数=买套餐的去重客户；二次券=现场掏钱买的代金券张数；
叠加率=全部行数量合计÷总客次；新客成交率=成交人数÷新客客次；员工「业绩」=该员工名下权益金（明细里「实业绩」列为 0）。

用户要求改口径时，改 `store_report.py` 并同步更新 README 与本文件。
