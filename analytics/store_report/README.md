# 门店经营报表（售出明细表 → 月度 / 周度 / 员工达成）

把收银系统导出的 **售出明细表** Excel 发给 Claude，就能拿到填好的经营报表，不用再自己做透视表。
口径和 2026-10 手工透视表逐项核对过：权益金 78,102、营业额 64,043.94、总客次 247、会员客次 26、
新客客次 212、网红/邀约 9、成交人数 18、成交客单 3,338、二次券成交数 79、体验客单价 259.29、叠加率 1.85。

## 用法

```bash
python3 analytics/store_report/store_report.py 售出明细.xlsx -o reports/门店经营报表.xlsx
python3 analytics/store_report/store_report.py 售出明细.xlsx --month 2026-10      # 文件含多个月时只取某月
python3 analytics/store_report/store_report.py 售出明细.xlsx --weeks natural      # 周一~周日 自然周
```

输入：只要 Excel 里有一个 sheet 含这些列即可（优先读名为「售出明细表」的 sheet，其他透视表 sheet 会被忽略）：
类型、分类、名称、数量、支付方式、支付金额、现金类支付、员工、客户名称、账务日期（客户编号、单据类型可选）。

## 输出的 Excel

| Sheet | 内容 |
|---|---|
| 经营报表 | 月度总数据、周度数据 W1–W5、员工达成（版式同手工模板） |
| 指标说明 | 每个指标的计算口径 + 本期数值 |
| 套餐成交明细 | 算「成交人数 / 成交客单」用到的每一笔套餐（相当于原来的 Sheet4） |
| 二次券成交明细 | 算「二次券成交数」用到的每一张券（相当于原来的 Sheet5） |
| 数据检查 | 未指定员工、退款、新支付方式、跨月等提示 |

新客客次、成交客单、体验客单价、叠加率都写成 Excel 公式，右侧灰色「计算用」列是公式的底数，改数会自动重算。

## 指标口径

| 指标 | 口径 |
|---|---|
| 权益金 | 类型=权益 的支付金额合计，排除「开业券 Voucher comprado online」（线上已付）；退款为负数抵扣 |
| 营业额 | 类型=项目 的支付金额合计（含代金券/套餐/免单核销的项目价值） |
| 总客次 | 类型=项目 的行数（退款单扣减） |
| 会员客次 | 类型=项目 且 支付方式=套餐 |
| 网红/邀约 | 类型=项目 且 支付方式=免单类 |
| 新客客次 | 总客次 − 会员客次 − 网红/邀约 |
| 成交人数 | 类型=权益、分类=套餐、现金类支付>0 的客户数（去重） |
| 成交客单 | 套餐现金类支付合计 ÷ 成交人数 |
| 二次券成交数 | 类型=权益、分类=代金券、支付方式不是 代金券/开业券/套餐/免单类 的数量合计（张） |
| 体验客单价 | 营业额 ÷ 总客次 |
| 叠加率 | 全部行「数量」合计 ÷ 总客次 |
| 员工·业绩 | 该员工名下的权益金（明细「实业绩」列全为 0，故不用） |
| 员工·营业额 / 总客次 | 该员工名下项目的营业额 / 行数 |
| 员工·成交人数 / 二次券成交人数 | 该员工名下买套餐 / 现场买券的客户数（去重） |

- **周度**：默认 1–7 日=W1、8–14=W2、15–21=W3、22–28=W4、29 日–月底=W5（按账务日期）；还没到的周留空，进行中的周标「截至 xx/xx」。
- **未指定员工（线上购券）**：明细里没填员工的记录（多为客人线上买券），单列一行，保证员工合计 = 月度总数。
- **员工名**：自动合并多余空格（如 `Thalita  Silvestre` → `Thalita Silvestre`）。
- 新出现的支付方式会默认按「现金类」计入权益金和二次券，并在「数据检查」里标红提醒，需要时在 `KNOWN_PAY_METHODS` / `pay_kind()` 里调整。

> 原始明细含客户姓名、手机号等信息，不要提交到仓库；`analytics/**/*.xlsx` 与 `reports/` 已加入 .gitignore。
