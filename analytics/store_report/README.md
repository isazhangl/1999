# 门店经营报表（售出明细表 → 看板 / 目标达成 / 月度 / 周度 / 员工达成 / 项目分类）

> 这就是门店**周报**：用户说「做周报」时，按 `.claude/skills/store-report/SKILL.md` 的步骤为每家门店出一份，
> 并按 `.claude/skills/store-report/周报汇报模板.md` 写中文汇报。

把收银系统导出的 **售出明细表** Excel 发给 Claude，就能拿到填好的经营报表，不用再自己做透视表。
口径和 2026-10 手工透视表逐项核对过：权益金 78,102、营业额 64,043.94、总客次 247、会员客次 26、
新客客次 212、网红/邀约 9、成交人数 18、成交客单 3,338、二次券成交数 79、体验客单价 259.29、叠加率 1.85。

> **2026-10-25 口径调整（用户要求）**：权益金加入线上开业券，并拆成 卖套餐 / 二次券 / 体验 / 线上卖券；当天就用掉的店内券从二次券移到体验，所以二次券成交数比上面的核对值小；员工业绩不含线上卖券。周度改为周一~周日。**客次改成到店次数**（同一客户同一天 = 1 客次，上面 247 是按项目行数算的，同一份数据按到店次数是 213），叠加率 = 项目次数 ÷ 客次，会员按客户编号（字母+数字）识别；另加人效。

## 用法

```bash
python3 analytics/store_report/store_report.py 售出明细.xlsx -o reports/周报_Ibirapuera_20261001_20261018.xlsx
python3 analytics/store_report/store_report.py 售出明细.xlsx --month 2026-10      # 指定报表月份（默认取数据最多的月份）
python3 analytics/store_report/store_report.py 售出明细.xlsx --weeks fixed        # 改回 1-7日=W1…（默认 周一~周日）
python3 analytics/store_report/store_report.py 售出明细.xlsx --targets 目标.json  # 指定目标文件
python3 analytics/store_report/store_report.py 售出明细.xlsx --store Morumbi      # 指定门店
```

**多门店**：门店按明细里出现最多的「权益归属门店」自动识别（`São Paulo - Unidade Morumbi` → `Morumbi`），
也可以用 `--store` 指定。门店名会写进所有标题和默认文件名（`门店经营报表_<门店>_<开始>_<结束>.xlsx`）。
目标按门店存：`analytics/store_report/targets/<门店>/<YYYY-MM>.json`，找不到就不出目标相关内容，
绝不会拿别的门店的目标凑数。现有 2026-10：Ibirapuera（权益金 260,000、营业额 126,000、总客次 350、新客成交率 20%、体验客单价 360）、Morumbi（权益金 140,000、营业额 100,000、总客次 250、新客成交率 20%）。

**输入格式**：表头不在第一行也可以（收银系统原始导出第一行是「售出明细表」标题，表头在第 4 行），脚本会自己找。

输入：只要 Excel 里有一个 sheet 含这些列即可（优先读名为「售出明细表」的 sheet，其他透视表 sheet 会被忽略）：
类型、分类、名称、数量、支付方式、支付金额、现金类支付、员工、客户名称、账务日期（客户编号、单据类型可选）。

## 输出的 Excel

| Sheet | 内容 |
|---|---|
| 看板 | 12 个 KPI 卡片（月度总数据全部指标；有目标的卡片显示「目标 · 同期 ✓/✗」和月达成进度条）；有目标时加 权益金/营业额 累计 vs 目标曲线、目标达成率 vs 应达进度、周度 实际 vs 目标；另外 4 张常规图：周度权益金构成（卖套餐/二次券/体验/线上卖券）、周度权益金 vs 营业额（无目标时）、周度客次构成（新客/会员/网红）、员工业绩 vs 营业额、项目分类客次（按客户类型）、项目分类营业额 |
| 目标达成 | 月度：月目标/实际/月达成率/同期目标/同期达成率/剩余需完成/剩余日均；周度：每周目标 vs 实际；每日：目标 vs 实际 + 累计达成率 |
| 经营报表 | 月度总数据（有目标时下面多 月目标/月达成率/同期目标/同期达成率 4 行）、周度数据、权益金拆解（月度 + 各周 + 占比）、员工达成·月度数据（版式同手工模板）、员工周度数据（每人「月度合计 + 各周」） |
| 人效 | 月度 + 各周：总客次、护理师人天、营业天数、日均上班护理师、人效；每日：总客次、上班护理师、人效、当天做项目的护理师名单 + 每日人效柱状图 |
| 项目分类 | 按分类（按**项目次数**，一次到店做两个项目算 2 次）：项目次数/占比、新客/会员/网红的项目次数（按那次到店的类型）、客户人数、营业额/占比、平均单价（营业额 ÷ 项目次数）；以及分类 × 周 的项目次数和营业额 |
| 项目明细 | 每个具体项目的项目次数、新客/会员/网红、客户人数、营业额、平均单价 |
| 指标说明 | 每个指标的计算口径 + 本期数值 |
| 套餐成交明细 | 算「成交人数 / 成交客单」用到的每一笔套餐（相当于原来的 Sheet4） |
| 二次券成交明细 | 算「二次券成交数」用到的每一张券（当天用掉的券算体验，不在这里） |
| 数据检查 | 未指定员工、退款、新支付方式、跨月等提示 |
| 图表数据 | 看板图表引用的数据 |

新客客次、成交客单、体验客单价、叠加率、新客成交率、占比、平均单价都写成 Excel 公式，右侧灰色「计算用」列是公式的底数，改数会自动重算。
表格里的蓝色数据条（权益金、营业额、客次、员工业绩等）方便一眼看出大小。
图表配色固定：权益金/业绩=紫、营业额=绿、新客=蓝、会员=橙、网红/邀约=青。

## 指标口径

| 指标 | 口径 |
|---|---|
| 权益金 | 卖套餐 + 二次券 + 体验 + 线上卖券（2026-10-25 起含线上开业券）；用代金券/套餐抵扣的部分不算（不是新收的钱）；退款为负数抵扣 |
| 卖套餐 | 类型=权益、分类=套餐 的支付金额（不含代金券/套餐抵扣部分） |
| 二次券 | 店里卖出（现金/卡/PIX）、当天没用掉的代金券；券的退款记在这里（负数） |
| 体验 | 做项目时直接付钱（类型=项目、现金/卡/PIX）＋ 店里现买、当天就用掉的券。「当天用掉」按客户逐日估算：当天用券做的项目先抵之前买的券、再抵当天登记的线上券，剩下的才抵店里现买的券（文件开始前买的券看不到） |
| 线上卖券 | 支付方式=开业券（客人线上已付）的权益行和项目行；没有销售员工 |
| 营业额 | 类型=项目 的支付金额合计（含代金券/套餐/免单核销的项目价值） |
| 总客次 | **到店次数**：同一客户同一天来店算 1 客次，不管做了几个项目（2026-10-25 起，之前按项目行数）；整次到店都退款的不算 |
| 会员客次 | 那次到店有套餐核销，或客户编号是字母+数字（如 B14；会员用券或直接付钱也算会员） |
| 网红/邀约 | 那次到店有免单类付款、且没有套餐核销 |
| 新客客次 | 总客次 − 会员客次 − 网红/邀约（客户编号纯数字、没用套餐也没免单的到店） |
| 成交人数 | 类型=权益、分类=套餐、现金类支付>0 的客户数（去重） |
| 成交客单 | 套餐现金类支付合计 ÷ 成交人数 |
| 二次券成交数 | 「二次券」的张数：现场掏钱买的代金券（现金/卡/PIX，或组合支付里有现金部分），去掉当天就用掉的（算体验） |
| 体验客单价 | 营业额 ÷ 总客次 |
| 叠加率 | 项目次数 ÷ 总客次：平均每次到店做几个项目（项目次数 = 类型=项目 的行数，拆分行不算，退款扣减） |
| 新客成交率 | 成交人数 ÷ 新客客次 × 100%（新客客次为 0 时留空） |
| 人效 | 总客次 ÷ 护理师人天（客次/人/天）。护理师人天 = 每天有做项目的员工人数相加（来自明细「员工」，不是排班表；上班但没做客人的不算，所以实际人效略低）。月度、周度表格各加一列，「人效」页有每日明细；看板「总客次」卡片下显示月人效 |
| 员工·业绩 | 该员工名下的 卖套餐 + 二次券 + 体验（不含线上卖券；明细「实业绩」列全为 0，故不用） |
| 员工·营业额 / 总客次 | 该员工名下项目的营业额 / 该员工服务的到店次数（两位员工服务同一次到店时各算 1 次） |
| 员工·成交人数 / 二次券成交人数 | 该员工名下买套餐 / 买二次券的客户数（去重） |
| 员工·新客成交率 | 该员工成交人数 ÷ 该员工服务的新客客次（灰色「计算用:新客客次」列）；只卖不做项目的员工留空 |
| 项目分类 | 类型=项目 的行按「分类」汇总，按项目次数算；新客/会员/网红按那次到店的类型；客户人数 = 做过该分类的去重客户；平均单价 = 营业额 ÷ 项目次数 |

## 中葡双语

报表所有表名、表头、标签、图表标题、卡片、说明和「数据检查」提示都是 **中文 + 葡萄牙语**：
表头上下两行（中文在上），其他标签写成「中文 / Português」，「指标说明」多一列葡语定义。
日期统一写成 `18/out` 这种「日/葡语月份」格式，避免 10/01 被看成 1 月 10 日。
术语对照在 `store_report.py` 的 `PT` 字典里，改词只改那里。

## 目标

每月一个 `targets/<YYYY-MM>.json`（不含客户信息，可以入库），格式见 `targets/2026-10.json`：

- `月目标`：指标名 → 月目标值。指标名用报表里的名字；「客单价」会自动当成「体验客单价」。比率写小数（20% 写 0.2）。
- `每日目标`：日期 → 当天的权益金目标（门店给的每日目标表）。只用来决定每天的权重：
  累加型指标（权益金、营业额、总客次…）的月目标都按这个比例拆到每天、再按周相加；休息日写 0。没给就按天平均。
- 比率型指标（新客成交率、体验客单价、成交客单、叠加率）每天/每周的目标都等于月目标。
- **目标进度** = 每日目标累计到报表最后一天占全月的比例；**同期达成率** = 实际 ÷（月目标 × 目标进度），≥ 100% 记 ✓。

2026-10 目标：权益金 260,000（原表 312,000 按比例下调）、营业额 126,000、总客次 350、新客成交率 20%、体验客单价 360。

## 其他说明

- **组合支付**：一行用两种方式付款时，系统会多出一行「数量 0」的拆分行。金额照算，不算客次，员工跟原行（2026-10 Morumbi 有 3 行）。
- **「品项」支付** = 体验券里包含的单个项目的核销，按代金券核销处理（算新客客次）。
- **类型=产品**（零售产品，如护发油）不计入权益金和营业额，在「数据检查」里单独列出。
- **周度**：默认 **周一~周日**（用户 2026-10-25 定的）。W1 = 包含 1 号的那一周，从那周的周一开始；跨月的周算满 7 天（例如 2026-10 的 W1 = 9/28–10/4，W5 = 10/26–11/1）。所以**导出明细时从 W1 的周一开始导**（10 月从 9/28 导）。上月/下月的那几天只进周度数据，月度、员工月度、每日和目标只算本月；文件没覆盖到 W1 的周一时，W1 标「从 xx/xx」并在数据检查里提醒。跨月的周目标：相邻月份有目标文件就用它补上那几天，没有就只比较本月的那几天（目标达成页会注明）。还没到的周留空，进行中的周标「截至 xx/xx」。`--weeks fixed` 可改回 1–7 日=W1 的旧口径。
- **未指定员工**：明细里没填员工的店内销售（线上卖券本来就不算员工业绩），单列一行。员工业绩合计 = 权益金 − 线上卖券。
- **员工名**：自动合并多余空格（如 `Thalita  Silvestre` → `Thalita Silvestre`）。
- 新出现的支付方式会默认按「现金类」计入权益金和二次券，并在「数据检查」里标红提醒，需要时在 `KNOWN_PAY_METHODS` / `pay_kind()` 里调整。

> 原始明细含客户姓名、手机号等信息，不要提交到仓库；`analytics/**/*.xlsx` 与 `reports/` 已加入 .gitignore。
